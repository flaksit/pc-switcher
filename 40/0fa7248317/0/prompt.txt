## Defect 1 — confirmed, with one correction to your brief

Your reading of the code was right. `_collect_plan_time_collateral` built one `trigger_ids` frozenset per direction from the whole candidate set and handed it to every collateral item, and `_resolve_collateral` overrode every one of those ids to `SKIP_ONCE` — including ids the user had decided `SKIP_ALWAYS`. `apply()` calls `_record_permanent_skips(plan, decisions)` on that overridden map (`packages/sync_core.py:367`, `:459`), so the permanent mark was never written.

One correction: the erasure is not limited to collateral's own batch semantics. Even with perfect attribution, a package that genuinely *is* a trigger and was marked `SKIP_ALWAYS` would still have lost its mark. My first version of the "skip-always survives" test used an *unrelated* package and came back GREEN under mutation M1 — attribution alone saved it. I rewrote it so the skip-always package is a real trigger; that is the test that actually pins the protection.

### Was exact attribution achievable, and at what cost

Yes, and cheaper than the ADR feared. The narrowing (`apt_sync.py:_collateral_for`) runs **only when the batched rehearsal already found manual collateral** — then it rehearses each candidate alone and blames it for the collateral its own transaction reproduces. Cost: **zero extra `apt-get --dry-run` on a clean run** (the common case, pinned by `test_a_clean_batch_costs_no_extra_rehearsal`), and **one per candidate in that direction** on a run that found collateral. A single candidate is its own answer and is not rehearsed twice, so the existing single-candidate tests still show exactly one simulation.

What is *not* exact, stated honestly rather than papered over: **joint causation**. apt keeps a package while either of two others is present and drops it once both go; no single candidate reproduces it. That collateral is attributed to the whole batch and the question says "the selected packages" rather than naming one. This is conservative and true, not an approximation dressed as exact. Isolating a minimal cause set there is delta-debugging over the candidate set, and I judged that disproportionate — it is documented as a negative consequence in ADR-020 instead.

The permanent-decision fix is independent of all of that: `_resolve_collateral` now downgrades only an `APPLY`.
