## The model, in short

The apt review becomes three screens: **packages** (each line naming its origin when that origin is not the distribution archive, in ruling-9 full-path form), **repository removals** (two answers — remove or skip once, no registry entry), and **repository conflicts** (only when a file differing on both machines feeds a target skip-always package; shows both file contents, overwrite or skip once). Everything else under `/etc/apt` is derived: repository adds from approved packages, keys as today, pins as an always-sync bucket, plus `ubuntu.sources` / `/etc/apt/sources.list` / `ubuntu-esm-*` written-and-updated but never removed.

Origin replication is established by mapping `installed_origins_by_package` on the source (reusing the policy output `capture_source_items` already fetches at `apt_sync.py:1117`) through `_parse_source_file`'s URIs to source files, and is enforced by a batched `apt-cache policy` on the target **after** `apt-get update` and **before** the first install: candidate origins must intersect the source's, or the item fails. That check, not the derivation, is the hard guarantee.

## Findings worth flagging

- **The pin is load-bearing, verified.** Ubuntu's `firefox` is `1:1snap1-0ubuntu5` at priority 500 (read on the dev machine). Epoch 1 outranks every unpinned vendor version, so adding the Mozilla repo alone still installs Ubuntu's package. Pins must travel. That drove pins into an always-sync bucket rather than a per-package derivation — simpler, and it avoids inventing a `Pin: origin` parser.
- **The second review can be deleted entirely.** Its repo-availability case dissolves because classification now reads the *source's* origins, which no run mutates. Its pin case dissolves only if the `HELD_OR_PINNED` echo goes — which I recommend, because that branch (`apt_sync.py:352-355, 366-376`) is also the cause of the open defect at `02-HANDOVER-package-review.md:62` (a pinned target package can never be removed or silenced).
