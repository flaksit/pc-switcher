## Findings — doc vs code where the CODE looks wrong (not fixed)

1. **flatpak `ORIGIN_MISMATCH` is not implemented.** ADR-020 D-41 states "A ref present on both machines from different remotes is therefore `ORIGIN_MISMATCH`, reported and never converged", and the snap/flatpak SPEC stages it as S2. `_diff_flatpak_refs` (`src/pcswitcher/jobs/flatpak_sync.py:618-645`) compares `version` only, so an equal-version pair from two remotes produces **no diff at all** and an unequal one produces a bare `VERSION_MISMATCH`. `grep ORIGIN_MISMATCH src/pcswitcher/jobs/flatpak_sync.py` → nothing. `_origin_refusal`/`_installed_origin_refusal` do not cover it: they guard an install, and this case issues none. Recorded as matrix row F23 (‼) and in the requirements doc's gap section.
2. **The filtered-remote warning is not implemented.** ADR-020 Consequences: "The run warns per affected remote rather than claiming the remote replicated"; SPEC S8. `_FLATPAK_REMOTES_CMD_TEMPLATE` reads `name,url,options` but nothing inspects `options` for `filtered`. Matrix row F24 (‼).
3. **`tests/unit/test_dry_run.py:6`** states "Returns SUCCESS/FAILED as expected (not SKIPPED)" as an existing decision. A non-interactive dry run of a package job with a non-empty plan now raises `JobSkipped` (`sync_core.py:522`, no dry-run exemption). The behaviour matches the ruling you gave; the test module's docstring asserts the opposite. Worth a one-line fix in that docstring, but it is a test file so I left it.
4. Minor: `_capture_file_digest`'s docstring (`apt_sync.py:1104-1110`) says "Verified: `sha256sum` on a missing path exits 1 and writes nothing to stdout", while the apt SPEC's residual-risk list (§11 item 4) records that as assumed from the documented contract rather than observed. Behaviour is right either way; one of the two claims is overstated.
