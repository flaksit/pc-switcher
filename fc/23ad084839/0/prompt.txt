## 3. Fix proposal

### 3.1 Correct predicates

They differ. Two predicates, one parse.

**Site B (source, `manual_installs_sync`) — replace entirely.**

New rule: a name from the source's `apt-mark showmanual` is `apt-no-candidate` iff its **installed** version has no repository origin, i.e. every origin row under its `***` version is `/var/lib/dpkg/status`. Nothing else — not `Candidate: (none)`, not block absence.

Signature to add to the shared module (§3.2):

```
def packages_installed_from_no_repository(
    policy_output: str, queried_names: Sequence[str]
) -&gt; frozenset[str]
```

- `queried_names` is required because the origins map omits a package entirely when it has no repo origin (`apt_sync.py:753`, `origins.setdefault` is only reached inside the `parts[1] != "/var/lib/dpkg/status"` guard) — "no origins" is representable only as absence, and absence needs the queried list to be distinguished from "never asked".
- Returns `{name for name in queried_names if not origins.get(name)}`, where `origins` is `installed_origins_by_package(policy_output)`.
- Docstring must state the precondition: **callers must pass only names known to be installed** (a not-installed name would be indistinguishable from a dpkg-only one). At the only call site that precondition holds by construction — the list is `apt-mark showmanual`.
- Deliberate consequence to document: a package hand-installed at version 2.0 while a repo offers 1.0 **is** flagged unreproducible. That is correct under D-18 — replicating *this machine's* installed version needs the `.deb`, not the repo's older one.

Call site change at `manual_installs_sync.py:402`: swap `_packages_with_no_candidate(result.stdout)` for `packages_installed_from_no_repository(result.stdout, manual_names)`. Nothing else in that function moves; the label at `:404` (`f"{name} (no apt candidate)"`) should be reworded to say what is now actually meant — e.g. name that no configured repository provides it — since "no apt candidate" is now literally false for every item it produces.

**Site A (target, `apt_sync`) — keep the predicate, decide separately about the blind spot.**

Keep `Candidate: (none)` as-is at `apt_sync.py:1234`. It answers Site A's question correctly.

The remaining gap (empty block ⇒ silently offered ⇒ `Unable to locate package` at apply) is a **separate open decision, not part of this fix**. Presenting the options rather than picking:

- **(i) Leave it.** Deliberate today, locked in by `tests/unit/jobs/test_apt_sync.py:1888`. Cost: every hand-`.deb` package on the source is proposed as an apt install that is *guaranteed* to fail, once per sync, forever — because the source-side fix in Site B does *not* suppress apt_sync's own diff (D-15 forbids the cross-job coupling that would; this is exactly the undecided matrix-A11 double-surfacing in handover §4).
- **(ii) Strict only in the second pass.** Make `_replanned_package_diffs` (`apt_sync.py:1991`) treat an empty block as unavailable, since after `apt-get update` no further repo work is coming. Cheap, but the second pass only runs when repository work was approved (`apt_sync.py:1885-1887`), so a run with no `/etc/apt` changes is unfixed.
- **(iii) Ask the source instead.** Have `apt_sync.capture_source_items` (`apt_sync.py:1126`) run one extra batched `apt-cache policy` on the **source** over the same `showmanual` list and reuse `packages_installed_from_no_repository`. A package that came from no repo *on the source* cannot come from a repo on the target either, independent of target repo state and of ordering — so it classifies deterministically at plan time, with no second-pass dependency and no cross-job coupling. Costs one read command on the source, and needs its own detail wording (`build_repo_unavailable_detail`, `apt_sync.py:267-272`, currently says "target's repositories offer no candidate", which would be the wrong sentence). Also requires a new entry in `_READ_ONLY_CALLS` (`tests/unit/test_mutates_audit.py:116` currently pins `capture_source_items` at 1 `run_command`).

Recommendation: **(iii)**, with (i) as the do-nothing fallback. It is the only option that fixes the case the handover actually observed (`code` proposed as an install that fails) without depending on whether the run happens to touch `/etc/apt`.

### 3.2 Where the shared parser lives

**New module: `src/pcswitcher/jobs/packages/apt_policy.py`.** Move `_installed_origins_by_package` (`apt_sync.py:737-775`), `_normalise_repo_uri` (`apt_sync.py:684-690`, its only dependency), and `_packages_with_no_candidate` (`apt_sync.py:597-615`) there as public functions; add `packages_installed_from_no_repository` alongside. Delete both `_packages_with_no_candidate` copies from `apt_sync.py` and `manual_installs_sync.py:142-163`.

Justification against **D-15** (`docs/adr/adr-020-declarative-package-convergence.md:79`, "one manager's diff on the shared base would make the other three inherit inputs they never supply"):

- D-15's stated harm is **inheritance**, on the shared *base class*. `apt_policy.py` defines no class and is not in `PackageSyncJob`'s MRO. `snap_sync` and `flatpak_sync` simply never import it and inherit nothing new. The `packages/` package is not exclusively `PackageSyncJob` — `state.py` and `review.py` are already free-function/standalone-class modules imported selectively.
- It also satisfies **D-18**'s actual constraint (`manual_installs_sync.py:17-18`, "never imports `apt_sync`") — the dependency runs `manual_installs_sync → apt_policy ← apt_sync`, with neither job importing the other. Today's alternative is what D-18 chose: duplication, justified at `manual_installs_sync.py:94-96` as "one duplicated line is cheaper than a shared-core coupling". That premise no longer holds — the correct parser is a ~25-line stateful indentation walker with three subtle rules (`***` marker, exact 8-space origin indent, dpkg-status skip), not one line. `apt_sync.py:778-786` documents the project's own precedent for what duplicating a parser of this size costs: `_pin_packages`/`_parse_pin_file` diverged and silently lost every name after the first.

If the user prefers to keep D-18's zero-shared-code rule literally, the fallback is to duplicate the *origin* parser into `manual_installs_sync` too — but then the report should note that the project now maintains two copies of a 25-line parser, and 3.1's shared-signature guidance applies per copy.

### 3.3 Should `_packages_with_no_candidate` be deleted?

**Retain, do not delete.** Move it to `apt_policy.py` and export it as `packages_with_no_candidate`; its single remaining caller is `apt_sync.collect_unavailable_item_ids` (`apt_sync.py:1234`), where it is correct. Delete only the `manual_installs_sync.py:142-163` copy.

Its docstring must be corrected on the move: the current one at `apt_sync.py:598-601` implies `(none)` is what apt prints for an uninstallable package, which §1c disproves. It should say: `(none)` means apt knows the name but will not install it (pure virtual, or every version pinned below zero — `docker.io` is the observed case); a name apt has never heard of produces **no block at all** and is therefore absent from the result, which the caller reads as "no evidence against".

### 3.4 Consequences

**`manual_installs_sync` detection flow (`manual_installs_sync.py:402` area).** No structural change: `_scan_no_candidate_apt_packages` keeps its shape (one batched policy read on the source, `manual_installs_sync.py:400-406`), `capture_source_items` (`:434-448`) keeps passing `manual_names` (now used for both the command and the predicate), and everything downstream — `filter_inert`, `plan()`'s snippet lookup at `:474-494`, the carved `UNREPRODUCIBLE_REVIEW_ACTION` group at `:497-526` — is unchanged. What changes is *which* items appear: on the user's P17, one wrong item (`docker.io`) disappears and five real ones (`brother-udev-rule-type1`, `brscan3`, `cnpg`, `code`, `falco-app`) appear. **D-18's calibration in the handover ("4 apt packages have no repo candidate") is superseded: the measured number is 5.**

Also `tests/unit/test_mutates_audit.py:152` pins `_scan_no_candidate_apt_packages` at 1 `run_command` — unchanged by this fix (still exactly one policy read).

**The second review (commit `089ea985`).** The handover's line reference is wrong: `_rereview_repo_invalidated_packages` is at **`apt_sync.py:1899-1989`**, not 1410-1441 (that range is inside `_diff_apt_sources`/the orphaned-packages detail). Its gate is `apt_sync.py:1885-1887`. Consequences:

- With Site A's predicate unchanged, the second review is **unaffected** by this fix. It calls `collect_unavailable_item_ids` through `_replanned_package_diffs` (`apt_sync.py:2002`) with the same semantics as the first pass, so a `(none)` → available transition after `apt-get update` still reaches the user the same run, exactly as the handover describes.
- If option (ii) or (iii) from §3.1 is adopted, the second pass changes meaning and needs its own test: under (iii), the *source-side* origin fact does not change after `apt-get update`, so a package classified unavailable-by-source-origin must **stay** unavailable across the re-diff rather than flipping to `INSTALL` and being re-offered. That is the one new invariant (iii) introduces.
- `manual_installs_sync` has no second review and is unaffected either way.
