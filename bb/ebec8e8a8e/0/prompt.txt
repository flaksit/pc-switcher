## Ranking: origin outranks version, and why

Origin is checked **before** version, following `apt_sync.py:729-740`. apt's stated reason carries over unchanged and flatpak's facts do not differ: two vendors' builds of one ref are numbered independently (Flathub and Flathub-beta both ship `org.mozilla.firefox` on their own scales), so "source has 128.0, target has 129.0beta" states a difference of *degree* where the real difference is of *provenance*, and hides a wrong-vendor finding behind a line the user reads as ordinary float. `REPORT_ONLY` is forced rather than chosen: origin stays out of `item_id` (untouched, per your note), so there is no install/removal pair to offer, and `flatpak install &lt;other remote&gt; &lt;installed ref&gt;` refuses anyway.

**One deliberate deviation from the phase spec.** `02-SPEC-snap-flatpak-derivation.md` §2.3 specifies "a plain inequality of two remote names". I compared **URLs** instead, per ADR-020 D-41's "Origin is compared by the remote's URL, never by its name" — the name comparison misses precisely the same-name-different-URL case `5fc3ac01` shipped the install guard for, and invents a mismatch for a remote the two machines merely renamed. Fallback to names only when a URL cannot be resolved (a ref whose origin remote was deleted). Both URL maps are the **unfiltered** captures (`flatpak_sync.py` `plan()`), so a skip-always on a machine's own remote cannot switch the finding off. ADR-020 needs no change — the implementation follows its text, not the spec's weaker restatement.

## Filtered remotes — measured, premise held

Docker `ubuntu:24.04`, Flatpak 1.14.6, two probes:
- `flatpak remote-modify --filter=&lt;path&gt; &lt;name&gt;` exits 0, adds `filtered` to `options` as its own comma-separated token (so the `no-gpg-verify` membership test is unaffected — verified with `no-gpg-verify,filtered`), and reports the path in a separate `filter` column.
- The path is stored **verbatim** as `xa.filter` in `&lt;installation&gt;/repo/config` and is not validated: a nonexistent path and a relative path are both accepted at exit 0. `--no-filter` clears it.
- Column widths: with `--columns=name,url,options` an unfiltered no-options remote prints **2** fields; with `filter` appended it prints **4** (empty options, `-` filter).

The ADR's premise held. **I did not name the filter path in the warning**, deviating from spec §2.8. Naming it requires widening `_FLATPAK_REMOTES_CMD_TEMPLATE` to a fourth column, after which a real line is *always* 4 fields — so every remote fixture in the 2400-line test file (including `FakeFlatpakTarget`) would have to be reshaped or it would model output the command cannot produce. ADR-020's Consequences require the warning, not the path. Recorded in the spec at §2.8.
