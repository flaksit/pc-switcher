## Requirement id convention

`PKG-FR-*` for obligations, `PKG-NG-*` for non-goals — 119 ids, no duplicates, every in-document cross-reference resolves to a definition (checked by script).

Source of the scheme: `docs/system/core.md` uses `&lt;DOMAIN&gt;-&lt;TYPE&gt;-&lt;TOPIC&gt;` as a bolded bullet label (`CORE-FR-SNAP-PRE`, `CORE-SC-ABORT`), and `docs/system/package-sync.md` line 3 already declares **Domain Code: `PKG`**. So `PKG-FR-*` is the repo's own scheme applied to this domain. `NG` is the one extension I made: the repo has no id'd non-goals (`core.md`'s "Out of Scope" is unlabelled bullets), but the brief requires negative requirements to be citable. I did **not** copy core.md's `[Principle]` tags — that would have meant inventing constitution mappings.

Rationale that is not itself a requirement sits on a `Why:` continuation line under its requirement, mirroring core.md's `Lineage:` continuation style.
