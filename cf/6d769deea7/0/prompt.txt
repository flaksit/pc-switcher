## Branch in `item_id` — decided YES, against the SPEC's ruling

`item_id` is now `flatpak:ref:&lt;scope&gt;:&lt;application&gt;/&lt;arch&gt;/&lt;branch&gt;` (`flatpak_sync.py:200`). Three reasons, the first of which the SPEC missed:

- **`(scope, application)` is not a unique key for a machine's own listing.** Two branches of one id coexist in one installation — that is what branches are for — and `plan()` folds captured items into `{item_id: item}` maps (`flatpak_sync.py:1046`, `_diff_flatpak_refs`), so one of the two rows was silently dropped.
- **The origin argument does not carry over.** Origin must stay out because `flatpak install &lt;other remote&gt; &lt;ref&gt;` on an installed ref refuses, so the install half of the pair could never run. A branch change's install half *can* run — branches coexist — so install-plus-removal converges to exactly the source's set.
- Both `install` and `uninstall` need the full ref anyway, so identity and command argument are one string rather than two facts that can drift.

The SPEC's residual risk "`flatpak uninstall &lt;application id&gt;` is assumed unambiguous" was **wrong and is now measured wrong**: `flatpak uninstall --assumeyes --user org.example.Nope/x86_64/stable` → `error: No installed refs found for ... with arch ... with branch ...`, i.e. it parses the full ref, and the bare id is ambiguous under exactly the two-branch condition. Removed from §10.

## What I compare to verify origin, and why

- **Pre-install** (`_origin_refusal`, `flatpak_sync.py:1327`): the target's **URL** and **gpg_verify**, re-read off the target (`_target_remotes_now`, cached per run, discarded on every remote write). Not the name — the name matched in the wrong-vendor case. Not `Collection:`/`Commit:` — both would need a new per-ref command, while the URL is already on `FlatpakRemoteItem` and is the thing that differs. Not `key_digest`: ostree's import *merges*, so a target that already trusted another key keeps the digests unequal forever, and refusing on it would refuse every install from that remote permanently.
- **Post-install** (`_installed_origin_refusal`, `flatpak_sync.py:1374`): the landed origin read off `flatpak list`, resolved through the same remote map to a URL. **`flatpak info --show-origin` deliberately not used** — it exits 1 both for "ref not installed" (data) and "installation cannot be opened" (probe failure), which ADR-022 D-03 forbids; the listing answers "not installed" as an absent row at exit 0, so the exit code becomes an unambiguous discriminator and `require_answer` fails the job once.
- Neither the plan-time query nor this run's own exit codes are admissible: `remote-add --if-not-exists &lt;name&gt; &lt;other url&gt;` exits 0 and changes nothing. `_converged_remote_scope_names` was deleted for that reason.
