<objective>
Retarget the VM integration suite to the corrected same-run behavior 02-22 delivers, and turn the perpetually-skipped apt-repository-state coverage into a real run.

Three edits, all in `tests/integration/jobs/test_package_sync.py`:
1. `test_continue_on_item_failure` currently enables only `apt_sync` (`_write_apt_sync_config`), but the three unowned-install snippets it authors are owned by `manual_installs_sync` (D-18) — with apt_sync alone they are inert, the sync exits 0, and the D-27 assertion is what CI flagged on PR #206. Enable `manual_installs_sync` and fix the stale `AptSyncJob.scan_unowned_installs` references.
2. `test_manual_installs_sync_pushes_registry_and_replays_snippet` seeds the same item on BOTH machines (an OLD body on the target, a NEW body on the source) purely to work around the old target-registry classification. With classification now source-based, author on the SOURCE only.
3. `test_apt_repository_state_dry_run_reviews_source_and_key_separately` skips whenever the fresh runner VMs have no vendor repo whose signing key lives in `/etc/apt/keyrings` on both machines — which is always, so ledger #2 has never actually been exercised. Set up a synthetic divergence instead.

Purpose: make the suite genuinely exercise D-27 continue-on-failure with source-authored snippets applied the same run, prove same-run snippet push+replay from a source-only registry, and give broken-window ledger #2 real, deterministic coverage.

Output: an updated integration module whose definitive proof is the green CI run gated by the existing 02-21 human checkpoint.
</objective>
