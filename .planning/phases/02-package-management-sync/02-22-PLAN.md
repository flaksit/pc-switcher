<objective>
Fix the `manual_installs_sync` defect the VM integration suite caught: a source-authored install-snippet is applied one run too late. `plan()` classifies an unreproducible item `INSTALL` only when its snippet is already in the TARGET registry, so a brand-new source snippet is `REPORT_ONLY` this run and the base `apply()` excludes it from converge; the post-review `send_file()` push transports the snippet this run but it converges only the NEXT run.

Corrected behavior (corrected D-23 in `02-CONTEXT.md`): reproducibility is judged by snippet availability **from the source**, and a snippet added on the fly during review is **applied** the same run. Two edits, both inside `manual_installs_sync` (the base stays generic, D-18): (1) `plan()` reads the source registry; (2) `after_review()`, after its finalize+push, reclassifies each on-the-fly-authored item `REPORT_ONLY → INSTALL` and forces its decision `APPLY`, so the unchanged base `apply()` converges it this run.

Purpose: make the sync exit non-zero when a source-authored snippet's converge genuinely fails (D-27), and make an install snippet a same-run reproduction rather than a deferred one.

Output: corrected `manual_installs_sync.py` + a stale docstring in `packages/state.py`, unit tests pinning the corrected same-run behavior, and consistent ADR-020 / package-sync.md.
</objective>
