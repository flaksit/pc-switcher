## Gaps

**A3 — an automatically-installed package on Nomad is never offered for removal.** Nothing asserts it. `AptProbe.query_target_items` reads `apt-mark showmanual`, so it holds by construction, but there is no regression test: a fixture where Nomad's `dpkg-query` lists `auto-dep` and its `showmanual` does not, asserting no `apt:package:auto-dep` diff. Unit test with mocks, trivially.

**A14 / A15 / A9's target half — the hand-`.deb` exclusion is source-side only.** `AptProbe.capture_source_items` filters `packages_installed_from_no_repository` out of the source manifest; `AptProbe.query_target_items` applies no such filter. Two consequences, both read from the code and neither executed:

- A14: a package installed from a hand `.deb` on BOTH machines is dropped from Atlas's manifest and kept in Nomad's, so `diff_apt_packages` sees a target-only item and emits `EXTRA_ON_TARGET`/`REMOVE`. That is an apt review line offering to delete software `manual_installs_sync` owns, and it also breaks `PKG-FR-APT-SAME` for a package both machines have. This is the one to fix first.
- A15: a hand-`.deb` package only on Nomad is likewise offered for apt removal.

Both are unit-testable with mocks: give the source `_POLICY_HAND_DEB` for `code` and put `code` in the target's `apt-mark showmanual`; assert no `apt:package:code` diff. The fix belongs at capture (exclude on the target the same way, which needs one batched `apt-cache policy` over the target's manual set — the run already issues one over Atlas's names, not Nomad's).

**A36 — a report-only package derives no repository file.** `OriginPlan.derived_files` returns empty for `UNREPLICABLE`, but the existing test only asserts no install. Add to `test_apt_origins`:`TestOriginClassification::test_unreplicable_origin_is_report_only_naming_the_origin` an assertion that the plan's `derived_files` is empty, matching the two class-1/class-2 tests beside it. Unit, with mocks.

**A40 — a credential in an origin URL.** `ItemDiff.__post_init__` runs `redact_credentials` over `label` and `detail`, and `test_redaction` covers the redactor, but no test drives an apt origin containing userinfo through the diff. One unit test: a source policy block whose origin is `https://user:pw@repo.example.test/apt`, asserting the install item's detail carries `***@` and not the password. Overlaps area G — leave it there if G claims it.

**A53 — removal never purges.** Add the `test_snap_sync`:`TestConvergeRemoval::test_removal_never_passes_purge` shape to `test_apt_packages`:`TestRemovalConverge`: assert no command containing `apt-get remove` also contains `purge`. Unit, with mocks.

**A58 — an ordinary install carries no version.** The helper `respond_to` matches fixture keys by substring, so `... --no-install-recommends pkg-a` matches a command ending `pkg-a=1.0`. Assert the exact command string instead (`any(cmd == "sudo DEBIAN_FRONTEND=noninteractive apt-get install --assume-yes --no-install-recommends pkg-a" for cmd in all_calls(target))`), which is the form the held-package tests already use via `_PINNED_INSTALL`. Unit, with mocks.

**A60 — origin divergence takes precedence over a version difference.** `diff_apt_packages` checks `is_origin_mismatch` in the `elif` branch before the version comparison, so it holds structurally, but the only test uses the same version on both sides. Copy `test_apt_origins`:`TestOriginClassification::test_divergent_vendor_provenance_reports_origin_mismatch` with Atlas at 1.0 and Nomad at 2.0 and assert the diff class is `ORIGIN_MISMATCH`, not `VERSION_MISMATCH`. Unit, with mocks.

**A62 / A63 — vendor-versus-distribution origin divergence is never raised.** `origins.is_origin_mismatch` returns `True` only when `vendor_source_origins` and `vendor_target_origins` are BOTH non-empty and disjoint. `vendor_target_origins` is the target's installed origins minus the target's own distribution origins, so a target copy served by the archive yields an empty tuple and the comparison short-circuits. Atlas's `gh` from `cli.github.com` against Nomad's `gh` from the Ubuntu archive therefore falls through to the version comparison — reported as a version difference if the versions differ, and as nothing at all if they match. That is exactly the case `PKG-FR-APT-IDENTITY`'s own "Why" names as two different pieces of software. The suppression's stated purpose (two machines on different mirrors) is already served by computing distribution origins per machine (A23), so the extra `bool(plan.vendor_target_origins)` condition appears to be over-broad rather than load-bearing. Needs a requirements ruling before a test: if the article is meant as written, drop the `vendor_target_origins` emptiness condition and add two unit tests (differing versions, and identical versions). Mocks suffice.

**No VM coverage of the origin model.** The only integration test touching D-34/D-35 is `test_package_sync`:`TestAptSyncEndToEnd::test_a_package_the_targets_apt_cannot_locate_still_reaches_the_review`, which is `--dry-run` and proves only that the plan survives class 3. Nothing on a VM proves that a real install from a derived vendor repository lands from that vendor, nor that the post-refresh verification refuses a wrong-origin install. That needs real apt semantics (candidate selection, epochs, pin priorities) and cannot be done with mocks — the existing `_install_from_a_repo_the_target_lacks` / `_remove_local_repo_package` helpers in `test_package_sync.py` are the scaffolding for it.
