## Where the tool does not do what the requirements say

Every row marked `‼`. Each was checked by reading the code named; none was observed on a running machine unless the entry says so. The criteria's own [Where the tool does not yet meet these requirements](../planning/package-sync-conformance-criteria.md#where-the-tool-does-not-yet-meet-these-requirements) records the costs already accepted — the two collateral limits and the two flatpak ones — and those are not repeated here. Everything below is new against that section.

**A14 — apt offers to remove software it does not own.** `AptProbe.capture_source_items` drops packages installed from no configured repository and says the exclusion "happens HERE and nowhere else"; `AptProbe.query_target_items` applies no equivalent filter. A package both machines installed from a downloaded `.deb` is therefore missing from Atlas's manifest and present in Nomad's, and diffs as a removal. `PKG-FR-DEB-OWNERSHIP` says `apt_sync` produces no item for such software in any configuration, and `PKG-FR-APT-SAME` says a package both machines have at the same version produces none either.

**C50, N12 — a repository can be deleted while the package that needs it stays.** `PKG-FR-REPO-DELETE` counts what still uses a repository "after this run's **approved** removals". `AptSyncJob` builds that set from the plan-time package diffs — the **proposed** removals — and `diff_apt_sources`'s own docstring says so. Nothing re-checks at converge. Approving a repository's deletion while declining its package's removal leaves the package installed with its origin gone. `flatpak_sync` counts against the machine's real state after its converge loop; apt has no equivalent.

**A62, A63 — a vendor build against a distribution build is never reported.** `origins.is_origin_mismatch` returns true only when both machines have a non-empty vendor origin set, and `OriginClassifier.classify` builds each as that machine's origins minus its own distribution origins. A copy served by the Ubuntu archive therefore has an empty set and the comparison short-circuits, so the case falls through to the version comparison — and produces no item at all when the two versions match. This is the worked example the user requirements give for two different pieces of software: `gh` from GitHub's repository against `gh` from Ubuntu's archive. `PKG-FR-DISTRO-ORIGIN` makes the distribution one origin per machine; the code treats it as no origin, which suppresses more than the mirror exemption buys.

**J115 — the Ubuntu Pro payload reaches the debug log.** `PKG-FR-ESM-PRIVACY` allows only whether Nomad is attached to be logged or shown. `AptProbe.target_pro_attached` issues `pro status --format json` through `RemoteExecutor.run_command`, which calls `_trace_output` unconditionally and emits `stdout: %s` at DEBUG — subscriber identity included — before `esm_gate` ever parses it. The existing test passes because its executor is a mock.

**K88 — the snippet registry is mirrored outside its own consent.** The registry lives at `~/.config/pc-switcher/package-snippets.yaml`, beside the decision files, but `folder_sync`'s non-overridable exclusion is the glob `*.decisions.yaml`, which does not match it. Wherever `~/.config` is a synced folder, `folder_sync` carries the registry Atlas→Nomad after the package jobs have run — the transfer `PKG-FR-REGISTRY-CONSENT` exists to gate, and one `PKG-FR-OUTCOME-SKIPPED` and `PKG-FR-NO-TERMINAL` both say must not happen when the job was skipped.

**C7 — files apt ignores are synced as pins and configuration.** Measured on this machine (apt 2.8.3, Ubuntu 24.04): `man 5 apt_preferences` requires files in `preferences.d` to carry no extension or `pref`, `man 5 apt.conf` requires no extension or `conf`, and `Dir::Ignore-Files-Silently` skips `~`, `.disabled`, `.bak`, `.dpkg-[a-z]+`, `.ucf-[a-z]+`, `.save`, `.orig` and `.distUpgrade` in all of them. `AptProbe.capture_dir_digests` passes an extension filter for `sources.list.d` alone, so a `99-vendor.bak` in `preferences.d` becomes an always-synced write from Atlas and an offered deletion on Nomad, though apt reads it on neither. `PKG-FR-APT-IGNORES` forbids treating such a file as configuration in any of add, change or remove.

**B27 — a hold outlives its package's mark and freezes a package that is not there.** `filter_inert` drops a marked package from Atlas's manifest, but the hold sets are read raw and `_drop_inert_diffs` looks up the hold's own id (`apt:hold:<name>`) against a mark recorded under `apt:package:<name>`. The hold item survives; `PackageConverger._hold_refusal` finds no package diff, reads that as "Nomad already has it", and runs `apt-mark hold` for a package Nomad does not have. That is the bookkeeping hold `PKG-FR-APT-HELD-TARGET` calls harmful, and it blocks every later attempt to install the package.

**K82 — data for a revision that did not converge is mirrored anyway.** `snap_sync_exclude_paths()` keeps each app's current-revision directory and excludes the rest, computed from Atlas's filesystem alone. It takes no decisions and no converge results, so where a revision change was declined or failed, `folder_sync` still writes Atlas's current-revision data into `~/snap/<app>/<atlas-revision>` on Nomad, whose snapd never installed it. The function's docstring states the assumption that makes the exclusion safe — that `snap_sync` converged the revision first — and a declined or failed item is exactly what breaks it. `PKG-FR-SNAP-DATA-BOUNDARY` forbids the result.

**K81 — with `snap_sync` off, every revision's data is mirrored.** The snap filters are emitted only when `_package_job_enabled("snap_sync")` holds, and that returns false both when the job is disabled and when the sibling map is absent. Nothing unconditional names anything under `~/snap`. `folder_sync` module's own comment records this as a deliberate trade, so it is a conflict between a documented choice and `PKG-FR-SNAP-DATA-BOUNDARY` rather than an oversight.

**B28 — a held package with no captured version installs unpinned.** `_plan_packages` admits a name into `_held_versions` only when a non-empty version was captured, and `PackageConverger._install` falls back to an unpinned `install_args([name])` otherwise, so `_held_version_refusal` is never reached and the package is frozen at whatever Nomad offered. `PKG-FR-APT-HOLD-VERSION` forbids the fallback. Reachability is not established by reading the code: the empty version is a defensive default, and `dpkg-query`'s measured non-zero exit on an unknown name would fail the job first.

**G72 — a registry entry's authoring record is overwritten without asking.** `_guard_registry_overwrite` compares bodies alone, while a `Snippet` also carries `label`, `authored_at` and `authored_on`, all of which the whole-file transfer replaces. `PKG-FR-REGISTRY-CONSENT` gates a transfer that would "lose or change an entry the target holds". What is lost is metadata — the replayed body stays byte-identical — so the consequence is narrow.

**H167 — the article overstates the automation hatch.** `PKG-NG-AUTOMATION-ENV` says a permanent answer given through the environment variable writes "a machine-specific mark **or an install snippet**". `_decisions_from_automation` returns decisions only, so `ReviewOutcome.snippets` is always empty on that path and no snippet can be authored through it. `review.py`'s own docstring already states the narrower, correct version, so this is the article to fix, not the code.

## Questions the requirements do not settle

Each is a place where two articles can both be satisfied only by choosing between them, or where the text does not reach the case. None is a defect until it is ruled on.

- **A15 — a hand-`.deb` package only Nomad has.** `PKG-FR-DEB-OWNERSHIP` says `apt_sync` produces no item for it in any configuration; `PKG-FR-APT-REMOVE` says any package Nomad has and Atlas lacks is offered for removal. The external review reads `PKG-FR-DEB-OWNERSHIP` as the more specific rule and therefore decisive, which would make the current removal a plain defect rather than a collision.
- **B41 — a hold added and its package removed in the same run.** Both can be approved, because Atlas can hold a package outside its own manual set. The code removes and then holds, leaving Nomad holding what it no longer has. The articles say the hold is decided separately from its software; they do not say what happens when the two answers contradict.
- **C — the conflict question is gated on the proposed installs.** `PKG-FR-REPO-CONFLICT` says the question is raised only for a repository this run writes because an approved package comes from it, but the question must be asked before the approvals exist. The code uses the plan-time superset, so a file can be asked about and then not written. Nothing is written wrongly; no article covers the outcome.
- **D47 — a mark recorded earlier in the same run.** `PKG-FR-COLLATERAL-MARKED` says such a mark must count and that the question must say the package is marked. The protection counts, but items are built before answers exist, so the question cannot name a same-run mark. Whether the second half is required is not decidable from the text.
- **E — whether a warning satisfies "a run MUST name".** `PKG-FR-SNAP-SIDELOAD` requires a run to name the sideloads it found. They are named in a job warning, not in the review or the report. On the warning reading the branch is covered; on the report reading it is unmet.
- **F118 — the filter article's unscoped clause.** "No filter may be in force on a remote **this run provisions**" is scoped; "a remote the source does not restrict MUST NOT stay restricted on the target" is not. Read literally the second would require touching remotes no approved application needs, which `PKG-FR-FLATPAK-REMOTE-DERIVED` forbids. The code takes the narrow reading.
- **F121 — a third-scope application and the remote count.** `PKG-FR-FLATPAK-THIRD-SCOPE` skips such an installation, but an application in it can still be the last user of a remote, and the parser cannot see it. Whether deleting that remote is acceptable is a decision, not a test.
- **G79 — a registry on Nomad that cannot be parsed.** It reads as empty, so a transfer that would lose every entry counts as additive and asks nothing. `PKG-FR-READ-FAILS-JOB` says silence must not be read as an empty set; whether an unparseable file is silence or data is not stated.
- **J — a plan of nothing but report-only findings.** `PKG-FR-NO-TERMINAL` makes a headless run report any job with a non-empty review as skipped. Two machines differing only in versions therefore produce a skipped job, though nothing was ever decidable. This follows the letter of the article.
- **K23 — `folder_sync`'s exclusions depend on which package jobs are enabled.** `PKG-FR-JOB-INDEPENDENCE` says no job's behaviour may depend on whether another is enabled. The gating is deliberate and the reason is recorded in the code: a path hidden from the mirror while its own job is off is invisible to every mechanism at once. The article needs a clause either way.
