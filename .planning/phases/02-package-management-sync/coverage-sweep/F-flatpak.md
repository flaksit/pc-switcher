## Gaps

- **F43 ‼ (`PKG-FR-FLATPAK-REMOTE-TRUST`, accepted).** A remote whose key Atlas holds via the ostree per-remote `gpgkeypath` option is replicated as holding no key: `_stage_source_keys` reads only `<installation>/repo/<remote>.trustedkeys.gpg` and `/usr/share/ostree/trusted.gpg.d`. Recorded as accepted in the criteria (flatpak never writes that option). A unit test can pin the accepted behaviour — set the source remote verified with no keyring digest and no anchors, assert `_warn_about_trust`'s warning and a plain `remote-add` — but proving the real key location needs a VM with a hand-edited repo config; not worth it.
- **F44 (`PKG-FR-FLATPAK-REMOTE-TRUST`).** `_anchors_to_import` imports every anchor file the target lacks, not the one the remote actually verifies against. Unit-testable: two anchor files with different digests on the source, target holding neither, assert how many `--gpg-import=` flags the write carries. Decide first whether narrowing is even possible — libostree does not say which anchor a remote used, which is likely why the code copies all of them; if it is not, the row is a documentation fix rather than a test.
- **F60 (`PKG-FR-FLATPAK-REPOINT`).** "Declining MUST fail EVERY approved application that needed the source's URL." Unit-testable: extend the `conflict_target` fixture with a second source application from the same remote, decline the conflict, assert both item ids appear in `PackageItemFailures.failures` and both messages cite the decision.
- **F63 (`PKG-FR-FLATPAK-REMOTE-DELETE`).** The "keeping … : target still installs …" log line is unasserted. Unit-testable with `caplog` at DEBUG on `pcswitcher.jobs.base`, mirroring `TestUnusedRemoteIsDeleted::test_a_dry_run_previews_the_deletion_and_issues_none`.
- **F66 (`PKG-FR-FLATPAK-REMOTE-DELETE`).** An application reported as an origin divergence must keep its remote. Unit-testable: Nomad holds the shared reference from a remote named `vendor-b` that Atlas does not configure (Atlas holds it from `flathub`), so the plan produces an `ORIGIN_MISMATCH` and `vendor-b` is target-only; assert no `remote-delete` for `vendor-b`. This is the one branch of the "counted against what the machine actually has" clause with no test at all.
- **F72 (`PKG-FR-FLATPAK-REMOTE-DELETE`).** "Deleting a remote MUST take its signing key with it" is delegated to flatpak and asserted nowhere. Needs a VM: after a run deletes a target-only remote, assert `<installation>/repo/<remote>.trustedkeys.gpg` is gone. Cheap to bolt onto the existing filter or derivation VM test.

Unit-testable: two source applications, two remotes, one of Nomad's remotes pointing elsewhere and untouched by derivation (mark it machine-specific-conflict-declined, or give the second application an origin the source does not configure); assert exactly one entry in `PackageItemFailures.failures` and the other reference present in `target.refs`.
- **F97, F98 (`PKG-FR-FLATPAK-REMOTE-FAILURE`).** Two applications sharing one failed remote, and the "source reports no such remote at write time" branch of `_write_derived_remote`. Both unit-testable with the existing `FakeFlatpakTarget(responses=...)` mechanism; the second needs the source's remote listing to answer differently between plan and apply, which the current `respond_to` table cannot express — use a side-effect function that changes its answer after the first call.
- **F110 (`PKG-FR-FLATPAK-FILTER`).** Add `assert "customremote" in ...` and `assert str(path) in ...` to `TestRemoteFilterReplicates::test_a_filter_flatpak_refuses_fails_the_app_and_quotes_the_error`.

Unit-testable by adding substring responses (`"mkdir --parents /"`, `"install --mode=0644"`) to `TestRemoteFilterReplicates._target`, and for staging by making `send_file` raise or the staging `mkdir` fail.
- **F116, F143, F144 (`PKG-FR-FLATPAK-PRIVILEGE`).** The system-scope filter write/apply and the system-scope repoint are never asserted to run under sudo, and the user-scope unwritable-path case is untested. - **F118 (`PKG-FR-FLATPAK-FILTER`).** Nomad restricting a remote no approved application needs.
